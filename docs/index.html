Documentation

Install it, run it, audit it.

Gate is a small TypeScript CLI: it turns a verdict into a local LiteLLM configuration and points OpenCode at it. gate.html is the why — task-class aliases, the audit model, the recovery argument. This section is the how.

Jump to the quickstart Read the narrative
What this is

A local activation tool, not a service.

Gate reads a verdict — a ranked candidate list plus one stable alias per task class, build and plan — and writes it into a local LiteLLM configuration and, unless told not to, your OpenCode config. It runs once per command, writes to a directory you own, and calls out to nothing except whatever verdict or evidence source you point it at.

There's no Limits Apply account, no dashboard, and no hosted verdict yet — see the roadmap below for what that would take.

Prerequisites

Four things, one of them optional.

Node
Node 20 or newer — the CLI's argument parsing uses Node's built-in parseArgs.
npm
Anything that runs npx. Building from a clone instead needs pnpm — this repository is a pnpm workspace.
LiteLLM
The proxy Gate configures but doesn't install or run — pip install 'litellm[proxy]' or equivalent.
A provider key
Only once you point Gate at real evidence. The bundled example fixture needs none.

No account exists to create. Nothing below uploads anything — profile.json, verdict.json and the audit log all stay under a directory on your own machine.

Install

One package, no runtime dependencies.

@limits-apply/cli ships as a single pre-built file — everything it needs is bundled into it, so installing it pulls nothing else down. Run it without installing at all, or put its one command — limitsapply — on your path. 

npx @limits-apply/cli --help
npm install -g @limits-apply/cli

Published from a tag by a workflow with npm provenance, so the registry can attest which commit produced the file you install. To build it from a clone instead: pnpm install && pnpm gate:build, then pnpm gate — see the CLI reference for every command and flag either way.

Quickstart

Six commands, against the hosted catalog.

current.json is the hand-verified candidate catalog joined with the committed Artificial Analysis snapshot — real rates, real endpoints, each carrying the page it was read on and the day it was read. Gate ranks it against your local profile; nothing is sent anywhere. 

limitsapply init
limitsapply update --evidence https://limits-apply.github.io/limits-apply/current.json
export LITELLM_MASTER_KEY=sk-local-anything
litellm --config ~/.config/limitsapply/litellm.yaml
limitsapply status
limitsapply status --smoke

Offline, or without an API key to spend? limitsapply update --example ranks the bundled fixture (packages/gate/fixtures/example-evidence.json) instead. Its models and endpoint are fictional, but every file gets written exactly the same way, so it still runs end to end.

~/.config/limitsapply is the default root only when neither LIMITSAPPLY_HOME nor XDG_CONFIG_HOME is set — see environment variables. Every command also takes an explicit --root.

Troubleshooting

What the CLI actually says when something's wrong.

no alias is deployed
Not one task class resolved to a candidate, so there would be nothing behind the proxy. On the default classes that means nothing cleared intelligenceFloor and nothing fit inside monthlyBudgetUsd once multiplied by the turn count — check both, or that your evidence has anything in range.
missing alias alias
The verdict selected a candidate for that task class but the generated config doesn't carry it. Named per class — missing plan alias on the defaults, missing bulk alias on a class you declared.
unexpected master key setting
The generated litellm.yaml doesn't read its master key from LITELLM_MASTER_KEY. That's a Gate invariant, not a setting — it means the file was hand-edited; the next update regenerates it.
proxy must bind to loopback
Same story: the generated host isn't 127.0.0.1. Gate refuses to activate a config that binds anywhere else.
opencode config … is not valid JSON
Gate won't touch an OpenCode config it can't fully parse — JSONC comments included. Nothing is written; remove the comments, or rerun with --no-opencode.
Unknown command
Exits 2 and lists every real command on stderr — see the CLI reference.
--smoke can't connect
It pings the proxy directly, so a connection refused reads as smoke build: fail and exit 3, not as a crash — on a no-op update too, where there is nothing to undo. Start LiteLLM first: on status a failed ping is only a report, but on update it restores the previous configuration where there is one, and where there isn't it says gate: kept rather than claiming a rollback that didn't happen.
Roadmap

What this doesn't do yet.

Every gap below is deliberate, not hidden — this register is what every other page on the site links back to when it touches one of these. Two entries are marked as non-goals: they are not waiting on work. For the gaps in the benchmark rather than in Gate, see Deliberately not built in the README, and Open risks in the methodology.

Hourly polling
Non-goal. Removed. Gate runs once per command — nothing schedules it.
A published library
Non-goal, for now. Only the CLI is on npm. Publishing @limits-apply/intelligence and @limits-apply/sources means a semver promise, and the ranking surface is still moving — one recent branch changed activate's signature, renamed a config-change type and split the harness writers out of their module. They stay internal until that surface stops moving.
Every harness but OpenCode, pi and Claude Code
Those three are the config writers Gate ships, and only OpenCode's runs on its own — pi and Claude Code are written when --pi or --claude-code names the file, never because Gate recognised a path. Codex's block is generated from code but pasted by hand: merging into an existing config.toml needs a TOML parser Gate doesn't carry. Cursor, Aider, Crush and Goose have no writer; T3 Code and Hermes wrap other harnesses rather than talking to an endpoint, so they wouldn't get one.
OpenCode records newer than its SQLite migration
quota scan and advise read OpenCode's per-message JSON files, and OpenCode ≥ 1.x writes opencode.db (SQLite) instead — on a current install both commands see only pre-migration history. Reading the database needs a reader Gate doesn't carry yet; until then the message directory they accept is the legacy one.
Quota windows from anything but OpenCode or the Claude subscription
quota scan reads OpenCode's own message records, and quota pull reads the Claude subscription's own usage windows. Every other access path still has to be recorded by hand with quota exhausted <domain> --resets <iso>.
Local plans inside a budget combination
Gate already routes to a local endpoint: includeLocal pools a declared local candidate with the priced ones, and the task class's intelligence floor — not its price — decides whether it wins. What still waits is the ledger's budget frontier, which combines subscription plans only. Routing needs no $/task figure for the machine; combining does, and that one can't be derived without knowing how many hours a day it runs. The methodology rules it out of Layer 1 for exactly that reason — it would need Layer 2 runs, which do not exist.
