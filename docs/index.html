Documentation

Install it, run it, audit it.

Gate is a small TypeScript CLI: it turns a verdict into a local LiteLLM configuration and points OpenCode at it. gate.html is the why — two aliases, the audit model, the recovery argument. This section is the how.

Jump to the quickstart Read the narrative
What this is

A local activation tool, not a service.

Gate reads a verdict — a ranked candidate list plus two stable aliases, build and plan — and writes it into a local LiteLLM configuration and, unless told not to, your OpenCode config. It runs once per command, writes to a directory you own, and calls out to nothing except whatever verdict or evidence source you point it at.

There's no Limits Apply account, no dashboard, and no hosted verdict yet — see the roadmap below for what that would take.

Prerequisites

Four things, one of them optional.

Node
Node 20 or newer — the CLI's argument parsing uses Node's built-in parseArgs.
npm
Anything that runs npx. Building from a clone instead needs pnpm — this repository is a pnpm workspace.
LiteLLM
The proxy Gate configures but doesn't install or run — pip install 'litellm[proxy]' or equivalent.
A provider key
Only once you point Gate at real evidence. The bundled example fixture needs none.

No account exists to create. Nothing below uploads anything — profile.json, verdict.json and the audit log all stay under a directory on your own machine.

Install

One package, no runtime dependencies.

@limits-apply/cli ships as a single pre-built file — everything it needs is bundled into it, so installing it pulls nothing else down. Run it without installing at all, or put its one command — limitsapply — on your path. 

npx @limits-apply/cli --help
npm install -g @limits-apply/cli

Published from a tag by a workflow with npm provenance, so the registry can attest which commit produced the file you install. To build it from a clone instead: pnpm install && pnpm gate:build, then pnpm gate — see the CLI reference for every command and flag either way.

Quickstart

Six commands, against the bundled example.

The example evidence fixture (packages/gate/fixtures/example-evidence.json) is fictional — its models and endpoint don't resolve to anything real — but every file gets written exactly the way it would with a real one, so this genuinely runs end to end. 

limitsapply init
limitsapply update --example
export LITELLM_MASTER_KEY=sk-local-anything
litellm --config ~/.config/limitsapply/litellm.yaml
limitsapply status
limitsapply status --smoke

~/.config/limitsapply is the default root only when neither LIMITSAPPLY_HOME nor XDG_CONFIG_HOME is set — see environment variables. Every command also takes an explicit --root.

Troubleshooting

What the CLI actually says when something's wrong.

missing build alias
No eligible candidate cleared the profile's intelligence floor. Check intelligenceFloor, or that your evidence has anything above it.
missing plan alias
No eligible candidate fit inside the monthly budget once multiplied by the turn count. Check monthlyBudgetUsd.
unexpected master key setting
The generated litellm.yaml doesn't read its master key from LITELLM_MASTER_KEY. That's a Gate invariant, not a setting — it means the file was hand-edited; the next update regenerates it.
proxy must bind to loopback
Same story: the generated host isn't 127.0.0.1. Gate refuses to activate a config that binds anywhere else.
opencode config … is not valid JSON
Gate won't touch an OpenCode config it can't fully parse — JSONC comments included. Nothing is written; remove the comments, or rerun with --no-opencode.
Unknown command
Exits 2 and lists every real command on stderr — see the CLI reference.
--smoke can't connect
It pings the proxy directly. If nothing is listening yet, the check currently fails hard with a connection error rather than a clean message — start LiteLLM first.
Roadmap

What this doesn't do yet.

Every gap below is deliberate, not hidden — this register is what every other page on the site links back to when it touches one of these.

A hosted current.json
No Candidate[] catalog exists anywhere in this repo yet. --verdict, --evidence and --example are the only sources Gate has.
Hourly polling
Removed. Gate runs once per command — nothing schedules it.
A published library
Only the CLI is on npm. @limits-apply/intelligence and @limits-apply/sources stay internal — no stable API, no types, no semver promise.
Rollback on a post-activation smoke failure
The network smoke check runs after activation and is reported, but doesn't yet trigger a rollback — recorded in docs/gate-parity.md.
Every harness but OpenCode
mergeOpencodeConfig is the only config writer Gate ships.
Local and pay-as-you-go inside one combination
The budget frontier combines subscription plans only — a local member needs a local $/task, a PAYG member needs per-model rates, and neither is in src/data/ yet.
Personalized verdicts over a real catalog
--evidence and --example rank whatever you hand them locally. There's no hosted catalog to personalize against automatically.
