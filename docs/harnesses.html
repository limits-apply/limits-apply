Harnesses

One harness writes itself. Three were wired by hand. The rest are honest about not yet.

build and plan resolve behind a loopback LiteLLM proxy, so any OpenAI-compatible client can use them — but Gate only generates a client's own config file for one harness today. This page says which, and what it would take for the rest.

Status

Three rungs, and none of them is the provenance ladder.

Every harness below carries one of three statuses — deliberately not the measured · observed · derived · chained · modelled ladder the benchmark tables use, since that ladder is about the strength of a figure, not whether Gate can talk to a tool yet.

Verified
Gate writes this configuration itself, and a test compares the published snippet to the code that writes it.
Recipe
A configuration a human ran once, on a dated day — not generated, not exercised in CI.
Planned
No integration code, no verified recipe. The snippet column stays empty.
Harnesses

Eleven rows. One is a real function call, three are a dated afternoon.

opencode is the only harness Gate writes to directly — the snippet on its card is generated straight from mergeOpencodeConfig, the same function gate.html describes. pi, codex and claude-code are each a Recipe: the block on the card was pasted into a real config and answered, but Gate does not write it and nothing catches it drifting. Pi answered on both aliases; Codex and Claude Code answered on build only, because the model behind plan that day was served in the chat-completions shape alone and neither the Responses nor the Anthropic endpoint could reach it. Everything else stays Planned until it has its own integration code and its own test, per the roadmap.
