The verdict

Every name. One ranking.

How a list of candidates turns into one alias per task class — build and plan by default — under the same rules whether they came from a real evidence file or the bundled example.

Where it comes from

Nothing is hosted yet.

A verdict ranks a list of candidates against a workload profile and produces one selection per task class the profile declares — build and plan ship as the defaults — plus everything that didn't make it, and why. There is no published current.json: no Candidate[] catalog exists in this repository yet (see the roadmap). Gate takes its candidates from whatever you hand it — a full verdict via --verdict, an evidence file via --evidence, or the bundled fixture via --example.

Effective cost

What a turn actually costs, per candidate.

effective cost = input + cached input × (1 − cache discount) + output

In dollars per turn, using the workload profile's token counts and each candidate's own per-million rates. Where a candidate publishes a finite allowance, capacity is that allowance divided by this same effective cost.

The build rule

Cheapest, above the floor.

build = cheapest frontier candidate above the intelligence floor

The frontier here excludes local candidates outright — build never resolves to one. Among what's left, whichever clears intelligenceFloor at the lowest effective cost wins; ties break toward the faster candidate. Any task class can pick this way, over its own floor.

The plan rule

Strongest, inside the budget.

plan = strongest frontier candidate within the monthly budget

Same non-local frontier, filtered to candidates whose effective cost times turnsPerMonth fits under monthlyBudgetUsd. Among those, the highest-intelligence candidate wins; ties break by cost, then by speed. Any task class can pick this way, under its own budget.

Dominance

Catalog-wide, not per plan.

A candidate is dominated, and dropped from the frontier, when another eligible candidate is at least as good on intelligence, cost and speed, and strictly better on at least one. Dominance runs across the whole eligible catalog, not scoped to one provider or one plan — a cheaper, faster, equally capable route from anywhere beats a locked-in one.

Rejections

Seven reasons a candidate never reaches the frontier.

incompatible
Gateway compatibility is not verified.
identity-workaround
The access path requires a prohibited identity workaround.
credentials
A required local credential is unavailable.
region
The access path is unavailable in the profile's region.
concurrency
The candidate's concurrency is below what the profile requires.
stale-evidence
Critical price evidence has expired.
exhausted
A quota window on this access path was observed closed and has not reopened yet. The only transient rejection of the seven, and the only one recorded on your machine rather than read from evidence.
