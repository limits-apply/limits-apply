CLI reference

Seven commands. No hidden ones.

Every command below comes straight from the CLI's own command table — limitsapply --help prints the same list, in the same order.

Commands

init · update · status · quota · advise · measure · evidence.

limitsapply init

Write the default local profile if none exists yet.

--root <value>
Gate root directory (default: LIMITSAPPLY_HOME, then $XDG_CONFIG_HOME/limitsapply, then ~/.config/limitsapply).

limitsapply update

Activate a verdict: write the LiteLLM config and point OpenCode at it.

--root <value>
Gate root directory (default: LIMITSAPPLY_HOME, then $XDG_CONFIG_HOME/limitsapply, then ~/.config/limitsapply).
--verdict <value>
Path or URL to a verdict snapshot.
--evidence <value>
Path or URL to an evidence snapshot, ranked locally against the global workload.
--example
Rank the bundled example evidence fixture instead of a real source.
--opencode <value>
OpenCode config path (default: OPENCODE_CONFIG, then $XDG_CONFIG_HOME/opencode/opencode.json).
--no-opencode
Skip writing the OpenCode config.
--pi <value>
Write a pi config at this path. Nothing is written without it — pi is never configured unless you name the file.
--claude-code <value>
Write a Claude Code config at this path. Nothing is written without it — Claude Code is never configured unless you name the file.
--smoke
Ping the aliases through the proxy after writing, and restore the previous configuration if they don't answer.
--proxy <value>
LiteLLM proxy base URL for --smoke (default: http://127.0.0.1:4000).

Local endpoints declared in profile.json as localCandidates join the ranking when includeLocal is set, and are probed before it: one that doesn't answer is written to quota.jsonl as a 15-minute closed window with source endpoint-probe, and sits the run out. What decides whether such a candidate wins is the task class's intelligence floor, never its price. On --verdict they are noted and ignored — a published verdict is not personalised.

Exactly one of --verdict, --evidence or --example is required — with none, update exits 2.

--smoke asks one question: is a proxy up and answering every alias the verdict routes? LiteLLM loads its config at startup, so the probe reaches whatever the running proxy already has, never the file Gate just wrote. Both halves of that cut: against a stopped proxy it rolls back a configuration never given a chance, and against a still-running old proxy it passes — the old config carries the same alias names, so the old one answers for the new one. Restart LiteLLM, then status --smoke, to check the verdict now serving. Without the flag, update writes and does not probe.

limitsapply status

Print the verdict currently active in this root.

--root <value>
Gate root directory (default: LIMITSAPPLY_HOME, then $XDG_CONFIG_HOME/limitsapply, then ~/.config/limitsapply).
--smoke
Also ping every routed alias through the LiteLLM proxy.
--proxy <value>
LiteLLM proxy base URL for --smoke (default: http://127.0.0.1:4000).

limitsapply quota

With no arguments, list the access paths recorded as exhausted. With exhausted <domain>, record that one closed its window. With scan <path>, read them out of OpenCode's own message records — one JSON file per message — mapping each providerID to a failure domain through the active verdict, and naming on stderr any provider it cannot map rather than dropping it. With pull --domain <domain>, read the official Claude Code CLI's own OAuth token and ask Anthropic's own usage endpoint how much of the subscription's own usage windows are used, recording the domain closed if any window is at or past 100% utilization.

--root <value>
Gate root directory (default: LIMITSAPPLY_HOME, then $XDG_CONFIG_HOME/limitsapply, then ~/.config/limitsapply).
--resets <value>
ISO timestamp the window is said to reopen at.
--domain <value>
Failure domain to record a pulled window against.
--credentials <value>
Claude CLI credentials path for quota pull (default: ~/.claude/.credentials.json).

A recorded window takes effect at the next update, which rejects every candidate on that failure domain until the timestamp passes. It counts nothing: Gate never knows how much of an allowance is left, only that a window was seen closed and when it was said to reopen.

pull reads that token to account against Anthropic's own API and never routes it anywhere else. A missing token, or one whose expiresAt has passed, exits 1 — sign in or refresh with claude and try again. If nothing is closed it exits 0 and writes nothing; if more than one window is closed it writes a single event at the latest of their reopen times, because the domain is one access path and isn't usable again until every closed window has reopened.

limitsapply advise

Price the last N days from what is already on this machine — nothing is activated, nothing is written, and no Gate root is needed. Two sources, each optional: OpenCode's own per-message cost field, summed per provider×model over the window (observed — the tool's own figure, never re-derived), and the Claude subscription's usage windows read through the official CLI's own OAuth token (observed), each paced against its stated length — utilization ÷ elapsed fraction, printed as derived with the formula. With --price, the break-even line: the window's spend normalized to the average month (× 30.4375 ÷ days, the same 365.25 ÷ 12 month every page prints) against the plan price.

--opencode <value>
OpenCode message storage directory (default: $XDG_DATA_HOME/opencode/storage/message, then ~/.local/share/opencode/storage/message).
--credentials <value>
Claude CLI credentials path for the usage windows (default: ~/.claude/.credentials.json).
--days <value>
Window to summarize, in days (default: 30).
--price <value>
Your plan's monthly price in USD — adds the break-even line against the metered-equivalent spend.
--export
Print a pre-filled measurement submission instead of the summary, ready for the GitHub issue form.

A source that cannot be read is named on stderr and skipped; only when neither source exists does the command exit 1. --export fills the submission with everything the machine knows — configurations, windows, tokens, OpenCode's own costs — and leaves the fields only you can know (plan, grading, evidence artifact) as prompts, because inventing them is exactly what the ladder forbids.

limitsapply measure

Wrap one graded run: read the Claude subscription's usage windows before and after — the provider's own report (observed) — execute the command after --, and append one run record to a JSONL evidence log. The outcome is the grader's exit code (0 is pass, anything else fail); partial exists only as a manual override.

--workload <value>
Versioned workload id the run executes (e.g. wl-001@v1).
--access <value>
Exact access path measured — the plan's name, or e.g. Anthropic API (metered).
--config <value>
Model and harness the run used (e.g. claude-opus-5 · Claude Code 2.1.x).
--outcome <value>
Manual override: pass, partial or fail. Without it the graded command's exit code decides.
--credentials <value>
Claude CLI credentials path for the usage windows (default: ~/.claude/.credentials.json). A missing file is a stderr note and empty windows, not a failure.
--out <value>
JSONL file the run record is appended to (default: measurements.jsonl in the working directory — run evidence belongs to the run's directory, not the Gate root).

A failed run is a recorded fail and exit 0 — the run's failure is data, not a CLI failure. Only unusable flags or a command that cannot be spawned exit non-zero.

limitsapply evidence

Build an evidence snapshot from a candidate catalog and an Artificial Analysis snapshot. Both inputs are files on disk — nothing is fetched — and every rate keeps the page it was read on and the day it was read. A catalog row missing a source, or naming an aaSlug the AA snapshot no longer publishes, is refused by name; it is never dropped in silence. This is how the hosted current.json is generated.

--candidates <value>
Path to the hand-verified candidate catalog.
--aa <value>
Path to the committed Artificial Analysis snapshot.
--out <value>
Path the evidence snapshot is written to.
--agents <value>
Path to the committed Artificial Analysis coding-agents snapshot. Needs --agent-pairs alongside it.
--agent-pairs <value>
Path to the hand-verified agent-pair catalog. Needs --agents alongside it.

It writes evidence, not a verdict: the ranking still happens locally, in update, against your own profile. The snapshot carries no capacity claim — a Layer 1 rate is a rate.

Exit codes

Four, and they mean the same thing every time.

0 — ok
The command did what it says.
1 — failed
A candidate was rejected, or a harness config couldn't be parsed. Nothing already active was overwritten.
2 — usage
Bad or missing arguments — an unknown command, or update with no verdict source.
3 — smoke
A ping to a routed alias didn't come back clean. From status --smoke that is all it means; from update --smoke the activation was rolled back and the previous configuration is active again.
Files & root

One root directory, five files.

Every command resolves its root the same way: LIMITSAPPLY_HOME, then $XDG_CONFIG_HOME/limitsapply, then ~/.config/limitsapply — or whatever --root says instead.

profile.json
Your local overlay. The only file you edit.
verdict.json
The verdict currently active on this machine.
litellm.yaml
Generated proxy configuration — an output, never a setting.
audit.jsonl
One line per transition: activation, no-op, failure, rollback.
quota.jsonl
One line per observed closed window. Local to this machine, never published.
litellm.yaml

It's JSON. That's not a bug.

litellm.yaml is generated as JSON, not hand-written YAML — and that's fine. JSON is a strict subset of YAML, and PyYAML, what LiteLLM's proxy loads its config with, parses it exactly the same as any other YAML document. The extension stays .yaml because that's what LiteLLM's --config flag expects; the contents don't need to look more YAML-like than this to be read correctly.

Environment

Four variables, none of them secret to Gate.

LIMITSAPPLY_HOME
Overrides the gate root outright — checked first, ahead of everything else.
XDG_CONFIG_HOME
If set and LIMITSAPPLY_HOME isn't, the root becomes $XDG_CONFIG_HOME/limitsapply, and the OpenCode default becomes $XDG_CONFIG_HOME/opencode/opencode.json.
LITELLM_MASTER_KEY
Read by LiteLLM itself, not by Gate — Gate only writes the setting name into litellm.yaml. The proxy binds to http://127.0.0.1:4000 and its master key setting is always LITELLM_MASTER_KEY.
OPENCODE_CONFIG
Overrides the OpenCode config path Gate writes to, ahead of the $XDG_CONFIG_HOME default.
